This walkthrough documents the implementation, execution, and results for Phase 3 of our local CPU-only parameter-efficient fine-tuning (PEFT) pipeline.

Technical Analysis of the Tuned Output
Prependings of Decision Maker Codes:
Observed Behavior: The tuned model prepends its outputs with numbers like 18001 or 18011 (e.g. 18001 The NRP's...).
Root Cause: The training Q&A pairs generated in cmg_qa_training_data.jsonl were built from raw DWP decision maker policy sections, which contain section headings such as 18001, 18002, 18011. Since almost all training targets in the JSONL file started with these numbers, the model learned this as a stylistic structure and prepended them when queried.
Repetition and Grammatical Loops:
Observed Behavior: Under greedy decoding, the model falls into infinite loop repetitions (e.g., repeating "The NRP's pension contributions are taxable income because the NRP is not a child of the paying parent...").
Root Cause: Fine-tuning an extremely small model (SmolLM2-360M) on a tiny dataset (80 Q&A pairs) with relatively strong learning rates (5e-4) and high LoRA parameters (r=32, α=64) causes severe overfitting and catastrophic forgetting. The model forgets normal sentence structure and conversational rules in favor of repeating high-frequency terms from the limited fine-tuning dataset.
Factual Accuracy:
The base model hallucinated non-existent agencies (e.g., Irish "Department of Social Protection (DSP)") or general AI warnings.
The tuned model successfully acquired the policy domain vocabulary (e.g. NRP, HMRC, ALO, liability), but fails to organize them into correct policy rules due to the overfitted repetition loops.
Recommendations for Phase 4
To resolve the stylistic leaks and repetitive loops, the following actions are recommended for the next phase:

Clean the Ingestion Process: Strip all numeric paragraph IDs (like 18001, 18011) and administrative reference brackets (e.g., 1 CSMC Regs 2012, reg 34) from the training dataset.
Hyperparameter Regularization:
Reduce the learning rate to 5e-5 or 1e-4 to make model parameter updates gentler.
Reduce LoRA Rank/Alpha (e.g., r=8,α=16 or r=16,α=32) to restrict the adapter's capacity and prevent over-memorizing the tiny Q&A dataset.
Increase dataset size (aim for 500+ diverse synthetic Q&A pairs).
Decoding Parameters: Configure the evaluation script to use nucleus sampling (e.g., temperature=0.7, top_p=0.9, and repetition_penalty=1.2) instead of strict greedy search to break repetitive loops.
Transition to RAG: For strict policy questions where factual correctness is paramount, fine-tuning a small 360M model is highly prone to hallucination. Implementing a Retrieval-Augmented Generation (RAG) pipeline using a local embedding model will yield significantly safer, more accurate results.
